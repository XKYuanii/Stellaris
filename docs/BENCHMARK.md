# 锁座基准实验规范

结论只能来自此实验数据，禁止预设“Lua 一定比锁快”。计划新增 `stellaris-benchmark` 模块执行以下实现的可重复压测：节目级 Redisson 锁、每座位分布式锁、旧 v31 全量 Lua、v5 ZSET 候选 + 有界 Lua CAS。

## 场景矩阵

| 维度 | 取值 |
| --- | --- |
| 购票数量 | 1、2、4 张 |
| 冲突度 | 低、中、热点节目高冲突 |
| 场馆规模 | 1 千、1 万、5 万座位 |
| 模式 | 手动选座、自动选座 |
| Redis 拓扑 | 单机、3 主节点 Cluster |
| 客户端并发 | 50、200、500 |

## 必须输出的指标

- 吞吐量、P50/P95/P99、拒绝率；
- Redis Lua 执行时长、Redis CPU、自动选座冲突重试次数；
- 重复售票数，以及 `BUSINESS_INVARIANTS.md` 中每条不变量的结论；
- 环境版本、JVM 参数、Redis 配置、数据规模和原始结果文件。

## 预期而非结论

小型 O(k) Lua 预计会优于热点分布式锁；旧脚本会随 `HVALS + 排序` 的场馆规模恶化；v5 的综合表现需由实际报告证明。
