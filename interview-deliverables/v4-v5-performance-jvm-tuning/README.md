# V4/V5 性能优化与 JVM 调优面试材料包

本目录保存可直接用于简历和面试答辩的结论。主结论采用两套明确区分的统计口径：100并发 A/B 使用7轮交替测试的中位数；容量结论使用已通过全部正确性门禁的最佳有效实测，并明确称为“最佳实测”，不表述为多轮稳定容量。

## 最值得写的结果

- 同机单实例、100并发自动配座：V4/V5各7轮，14轮均为100%请求成功、订单全量落库、恢复终态`PASS`。
- 成功TPS中位数：`11.60 -> 943.40`，提升`8032.76%`，即`81.33倍`。
- 成功请求P99中位数：`8540ms -> 104ms`，降低`98.78%`。
- 3秒SLO达标率中位数：`33% -> 100%`，提升`67个百分点`；等价地，SLO违约率从`67%`降至`0%`。
- 固定SLO为成功率不低于99%且P99不超过3秒：V4经5轮确认的通过档为20并发；V5最佳有效实测为1000/1000成功、P99 1028ms、SLO达标率100%、恢复`PASS`。若写容量，只写“最佳实测由20提升到1000，50倍”，不要写成“稳定容量提升50倍”。
- JVM资源治理：将9个IDEA业务JVM裁剪为Program、Order、BaseData三个压测JVM，累计最大堆由36288MB约束到2048MB，降低94.4%；线程数由1667降到672，降低59.7%；驻留内存合计降低31.1%。

## 表述边界

- 这是“自动配座同步接单热路径”优化，不是整个下单端到端链路提升81倍。
- V4同步返回前会等待Kafka发送结果；V5同步返回边界是Redis Lua完成锁座并原子写入Redis Stream。两版的异步订单均用“最终全部落库、无超卖、恢复PASS”补充校验。
- 100并发下两版请求成功率都是100%，因此不能写“失败率降低”；应写“3秒SLO违约率从67%降至0%”。
- 吞吐使用TPS，不把一次性1000并发写成1000 QPS。
